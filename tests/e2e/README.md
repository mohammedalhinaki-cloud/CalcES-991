# Browser acceptance tests

Run `npm run test:e2e` for the Vite development server, or
`npm run test:e2e:production` to build and test the actual `build/web` artifact.
Both configurations start their own server on port 5174; keep it free.
Install Chromium with `npx playwright install chromium`, or set
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`.

The same display, keypad, scientific, advanced-mode and history flows run in both
configurations. `acceptance.spec.ts` additionally tests failure recovery and
exclusion of unsuccessful calculations from history. Its artifact-only case checks
local font resources, the hashed production worker, and a fresh reload; it is
intentionally skipped in development.

`fixtures.ts` automatically watches the default Playwright page for page errors,
console warnings/errors, HTTP failures and resource failures. In production it
also blocks external HTTP dependencies. Tests creating their own mobile contexts
attach their own runtime listeners. Native MathLive selection is checked in the
browser, not mocked in jsdom. Integration comparisons use numerical tolerances;
display formatting is checked separately.

Touch coverage uses Chromium mobile/touch emulation. Physical Android/iOS phones,
Safari and Firefox have not been validated. See `docs/acceptance.md` for scope.

`app-actions.spec.ts` checks collapsible data workspaces, native share cancellation,
clipboard/manual fallbacks, browser installation prompts and installed-state updates.
Its production-only case verifies manifest icons, app installability requirements
(except the isolated test context's incognito restriction), waits for precaching,
then reloads offline and computes an integral in the cached worker. The service
worker is generated by `postbuild` from all deployed resources. Normal persistent
Chromium profile installability was also checked separately without the incognito
exception; production browser simulations do not prove installation on a physical
phone.

`viewport.spec.ts` verifies that all 50 existing keypad buttons have bounds inside
the viewport and that the document itself has no vertical or horizontal overflow.
It covers short phones, live viewport height changes, landscape, and desktop, then
checks layers, error notices and internally scrolling tool panels. This checks
actual visibility rather than relying on clipping the page with overflow:hidden.
