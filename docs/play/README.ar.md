# تجهيز Android وGoogle Play

الحالة: مشروع Android محلي باستخدام Capacitor 8، حد أدنى Android 7 / API 24، وcompile/target SDK 36. الملفات والحسابات والخطوط والعامل مضمنة في التطبيق، دون الاعتماد على فتح موقع بعيد. لم يُنشأ تطبيق في حساب Play Console ولم تُرفع حزمة إليه.

## الهوية الحالية

- الاسم المعتمد: **CalcES 991 - حاسبة علمية**؛ على الأجهزة العربية: **CalcES 991 - حاسبة علمية**.
- معرّف الحزمة: `calces991.calculator`.
- الإصدار: `1.0.0`، versionCode: `2`.
- الاسم معتمد؛ معرّف الحزمة ما زال للمراجعة قبل أول رفع. يمكن تغيير الاسم لاحقًا، لكن يجب اعتماد معرّف الحزمة قبل أول رفع؛ لا يمكن استبداله لنفس إدراج Play بعد النشر.
- عند تغيير معرّف الحزمة قبل النشر، حدّث `capacitor.config.ts` وapplicationId/namespace في `android/app/build.gradle` وحزمة Java ومسارها، ثم نفّذ sync وابنِ من جديد.

## الملفات المسلّمة

- `build/android/study-tools-debug.apk`: نسخة اختبار موقعة بمفتاح Android التطويري المعتاد، ليست للرفع إلى Play.
- `build/android/study-tools-release-unsigned.aab`: حزمة إصدار غير موقعة ومعطلة الإعلانات الحقيقية؛ مرجع جاهز للبناء والتوقيع، لا تقبل Play رفعها بصورتها غير الموقعة.
- `build/android/study-tools-android-source.zip`: مصادر التطبيق وتعليماته دون node_modules أو SDK أو كلمات مرور أو مفاتيح.
- `docs/play/assets/store-icon-512.png`: أيقونة متجر 512×512، بخلفية غير شفافة.
- `docs/play/assets/feature-graphic-1024x500.png`: صورة مميزة 1024×500.
- `store-listing.ar.md` و`store-listing.en.md`: مسودتا وصف المتجر.
- `privacy-policy-template.ar.md`: سياسة خصوصية تحتاج بيانات الناشر ومراجعة إعدادات الإعلانات قبل نشرها.
- `app-ads.txt.example`: مثال يحتاج معرّف الناشر الحقيقي قبل رفعه على نطاق موقع الناشر.

## التثبيت والبناء على جهازك

المتطلبات: Node 22.12+ أو 24، JDK 21، Android System WebView محدث (Chromium 107+ على الجهاز)، وAndroid Studio حديث مع Android SDK 36 وBuild Tools 36.0.0. سيحمّل Gradle 8.14.3 الاعتمادات في أول تشغيل. Android Gradle Plugin هو 8.13.0. لا تحتاج Firebase أو google-services.json لتشغيل هذه الإعلانات.

```sh
npm ci
npm test
npm run android:sync
npm run android:open
```

في Android Studio اختر JDK 21 وأكمل تثبيت SDK والتراخيص المطلوبة. أو اضبط `JAVA_HOME` و`ANDROID_HOME` في بيئتك ثم:

```sh
npm run android:debug
npm run android:bundle
```

`android:sync` يبني نسخة الويب ثم ينسخها إلى Android. بعد تغيير React/CSS يجب تشغيله قبل بناء Android، وإلا ستبقى الملفات المضمّنة القديمة. APK وAAB الناتجان من أوامر npm يُنسخان إلى `build/android/`. الحاسبة لا تستخدم Service Worker في Android؛ الملفات المضمنة تكفي للعمل محليًا. نسخة الموقع/PWA تبقى على منطقها السابق.

## الإعلان العلوي

يستخدم Android مكتبة `@capacitor-community/admob` 8.2.1 مع Google Mobile Ads SDK 25.4.0 وGoogle UMP 4.0.0، مثبتة الإصدارات. الإعلان الوحيد هو **Anchored Adaptive Banner** أعلى الشاشة، دون App Open أو Interstitial أو Rewarded أو مؤقت إعادة تحميل يدوي. الصوت مكتوم، وتُحجز مساحة البانر المقاسة من SDK مع 6dp فراغ من الجهتين قبل عرضه. تتكيف الحاسبة مع الارتفاع المتبقي وتحتفظ بجميع أزرارها. في الوضع الأفقي يمتد حجز الإعلان فوق الشاشة والأزرار، ولا يمر فوق صف المفاتيح.

عند فتح نافذة HTML يُخفى الإعلان مؤقتًا دون تقليص الحجز؛ يعود بعد إغلاقها إذا كانت الموافقة تسمح. إذا فشل تحميل الإعلان أو تحديث الموافقة تستمر الحاسبة، وتبقى المساحة هادئة دون إلحاح أو نوافذ إعلانية.

`debug` يفرض معرّفات Google التجريبية على مستوى Gradle وJavaScript، حتى لو وضعت معرّفات حقيقية. لا تختبر بالنقر على إعلاناتك الحقيقية. `release` لا يطلب إعلانات افتراضيًا، إلى أن تضبط الإعدادات أدناه. نجاح بناء APK لا يثبت أن حساب AdMob مُفعّل أو أن وحدة الإعلان مرتبطة بحسابك؛ افحص ذلك على جهاز حقيقي بعد ضبطه.

## ربط حساب AdMob

انسخ `android/publisher.properties.example` إلى `android/publisher.properties`، وهو مستبعد من Git، ثم اضبط:

```properties
ADS_ENABLED=true
ADMOB_APP_ID=ضع_معرف_تطبيق_AdMob_هنا
ADMOB_BANNER_ID=ضع_معرف_وحدة_Banner_هنا
APP_AUDIENCE=general
PRIVACY_POLICY_URL=https://your-domain.example/privacy
SUPPORT_EMAIL=عنوان_الدعم_الحقيقي
APP_VERSION_CODE=2
APP_VERSION_NAME=1.0.0
```

صيغة **AdMob App ID** تحتوي `~`، وصيغة **Banner Unit ID** تحتوي `/`. ليست هذه مفاتيح API أو كلمة مرور حسابك. كإعداد بديل يمكن تمرير المتغيرات البيئية بالأسماء نفسها؛ لها أولوية على ملف الإعداد.

`general` يعني تطبيقًا غير موجّه للأطفال. `children` يفعّل COPPA وTFUA وطلب NPA وتصنيف محتوى G؛ هذه إشارات تقنية، ولا تستكمل وحدها جميع متطلبات Families أو اختيار أعمار الجمهور في Play. الجمهور المختلط يحتاج بوابة عمر محايدة قبل تفعيل الإعلانات؛ ليس مفعّلًا افتراضيًا. لا تضع `general` افتراضًا إن كان التطبيق موجّهًا للأطفال.

في AdMob أنشئ تطبيق Android ووحدة Banner، ثم اضبط **Privacy & messaging** للبلدان المستهدفة. يحدّث التطبيق UMP قبل تهيئة الإعلان، ويعرض نموذج الموافقة عند الحاجة، ولا يطلب إعلانًا إلا إذا أعادت UMP `canRequestAds=true`. يوجد مدخل «الخصوصية» بدل زر تثبيت الويب في تطبيق Android؛ منه يمكن فتح سياسة الخصوصية وخيارات موافقة الإعلانات عندما تتطلبها UMP. لا ترسل معرّفات جهاز الاختبار أو debugGeography مع الإصدار العام؛ الكود لا يفرض منطقة موافقة اختبارية في الإنتاج.

اضبط تصنيفات المحتوى والفئات المحظورة ومعدل تحديث البانر المناسب في AdMob؛ لا تضف مؤقت إعادة تحميل أو تنسيقات تغطي الحاسبة. انشر app-ads.txt الفعلي على نطاق موقع الناشر المسجل في المتجر عند ربط الإعلانات، ولا ترفع ملف المثال كما هو.

## التوقيع ورفع الحزمة

استخدم **مفتاح رفع Upload Key خاصًا بك**؛ المشروع لا يولّد مفتاح إنتاج ولا يطلب منك إرساله في المحادثة. يمكن إنشاؤه محليًا من Android Studio عبر Build → Generate Signed Bundle / APK → Android App Bundle. احتفظ بالمفتاح وبياناته خارج Git وخذ نسخة احتياطية آمنة.

للبناء من الأوامر، أضف إلى `android/publisher.properties`:

```properties
UPLOAD_KEYSTORE_PATH=المسار_إلى_ملف_مفتاح_الرفع
UPLOAD_KEY_ALIAS=اسم_المفتاح
UPLOAD_KEYSTORE_PASSWORD=كلمة_المرور_محليًا_فقط
UPLOAD_KEY_PASSWORD=كلمة_مرور_المفتاح_محليًا_فقط
```

المسار المطلق أو النسبي إلى جذر المستودع مدعوم. لا تضع كلمات المرور في package.json أو ملفات المصدر، ولا تشارك مفتاح الإنتاج أو ملف إعداداته.

```sh
npm run android:check-release
npm run android:release
```

يفحص الأمر الأول وجود بيانات الناشر والخصوصية والجمهور ومفتاح الرفع، ويتحقق من صيغة معرفات AdMob إذا كانت الإعلانات مفعلة. ليس فحصًا لحساب AdMob أو اعتمادًا قانونيًا لسياسة الخصوصية. يمكن بناء إصدار دون إعلانات بـ`ADS_ENABLED=false`، لكن يجب أن تطابق إجابات Play حالته الفعلية والمكتبات المضمّنة.

اختر AAB الموقّع الناتج من `build/android/study-tools-release.aab` وارفعه إلى **Internal testing** أولًا، وفعّل Play App Signing وفق إعدادات حسابك. كل تحديث لاحق يحتاج versionCode أكبر، مع الإبقاء على applicationId نفسه واستعمال مفتاح الرفع الصحيح. نفّذ متطلبات الاختبار المغلق التي تظهر لحسابك قبل طلب Production عندما تطلبها Play Console.

## إعداد إدراج المتجر

1. اعتمد الاسم ومعرّف الحزمة وبريد الدعم وبيانات الناشر.
2. انشر سياسة الخصوصية النهائية على رابط HTTPS متاح بلا تسجيل دخول؛ أضف الرابط هنا وفي Play Console. ملف السياسة المرفق مسودة وليست صفحة منشورة.
3. املأ Store listing بالنصوص والأيقونة والصورة المميزة المرفقة. التقط على الأقل صور الهاتف المطلوبة من APK النهائي، لا من عرض الموقع أو مسودات المتجر.
4. أكمل **Contains ads** و**Advertising ID** و**Data safety** و**Target audience** و**Content rating** و**App access** حسب النسخة التي سترفعها. الإعلان الحقيقي هنا AdMob، وليس شيفرة AdSense للويب.
5. الحاسبة لا تتطلب حسابًا أو تسجيل دخول، ولا تتضمن شراءً داخل التطبيق. لا تضف تعليمات دخول وهمية في App access.
6. راجع `release-checklist.ar.md` على هاتف فعلي قبل الإنتاج.

## الاختبارات والحدود

اختبارات الحساب والمحرر والموقع ما زالت مستقلة عن Android. اختبارات `bannerSession.test.ts` تتحقق من منع الإعلان دون موافقة، ومعرّفات الاختبار، وترتيب حجز المساحة، والكتم، والإخفاء وإزالة الإعلان عند تغيير الموافقة. اختبارات المتصفح تحاكي حجز بانر 50 و90dp في المقاسين الأفقي والرأسي دون تغطية الأزرار.

بناء APK/AAB وفحص Android Lint ليسا بديلًا لاختبار تطبيق فعلي. لم تُختبر نافذة UMP الأصلية أو عرض AdMob على هاتف صاحب الحساب، ولم يُرفع شيء إلى Play Console، ولم يُنشر تعديل على Cloudflare في مهمة تجهيز Android هذه. تحقق من متطلبات Play الحالية في لوحة حسابك عند الرفع، وبخاصة API المستهدف وإقرارات SDK والجمهور.
